# Беклог

Единственное место открытых задач проекта с {{DATE}}. Планов, списков «осталось» и TODO в других
документах не заводим: замеченную недоделку — задачей сразу, длинный план — документом рядом с
кодом, на который ссылается задача.

## Что где

| Файл | Что | Кто читает |
|---|---|---|
| [INDEX.md](INDEX.md) | Сводка: где нужен владелец, быстрое, на ночь. **Собирается скриптом** | Каждая сессия — первым |
| {{AREA_TABLES}} | Все открытые задачи области строкой таблицы. **Собираются скриптом** | Сессия своей области |
| {{AREA_DIRS}} | Открытые задачи, по файлу на задачу | Только нужную |
| [inbox.md](inbox.md) | Идеи и хотелки одной строкой, ещё не разобранные | Владелец пишет, сессия разбирает |
| [done/](done/) | Журнал закрытых задач по месяцам | Когда нужна история |
| [config.json](config.json) | Области, исполнители, места, метки, заморозка | Кто меняет устройство беклога |

Области:

{{AREAS}}

**Заморозка области.** Область, которую владелец заморозил, стоит в `frozen` у
[config.json](config.json) с причиной и датой. Её задачи остаются в беклоге, но сессии их не берут,
а INDEX.md и `list --owner`, `--quick`, `--night` их не показывают. Размораживает только владелец:
тогда строку убирают из `frozen` и пересобирают индекс.

## Задача

Файл `<область>/<ID>.md`, ID — {{ID_EXAMPLES}}.

```markdown
---
id: {{EXAMPLE_ID}}
title: Короткий заголовок               # до 70 знаков
priority: P2                            # P0 блокирует · P1 важно, ближайшие дни · P2 обычное · P3 когда-нибудь
executor: {{OWNER}}                         # {{EXECUTORS}}
autonomous: no                          # yes — агент делает и проверяет сам, годится на ночь
                                        # partly — агент делает, владелец проверяет или решает в конце
                                        # no — без владельца не начать: вход, устройство, решение
effort: 5m                              # 15m, 2h, 1d, 2-3d — работа исполнителя
where: any                              # {{WHERE}} — где делается
due:                                    # YYYY-MM-DD, если есть срок
tags: [check]                           # словарь ниже
block:                                  # необязательно: функциональный блок из `blocks` в config.json
related: [{{EXAMPLE_ID_2}}]                    # связанные задачи, в том числе пара «перенос»
after: [{{EXAMPLE_ID_2}}]                      # только если не начать, пока эти не закрыты
created: {{DATE}}
from:                                   # откуда пришла: документ и раздел, проверка, разговор
---
Что сделать — один-три абзаца.

**Владельцу:** что именно от него нужно (если autonomous не yes).
**Готово, когда:** проверяемый выход.
**Контекст:** чем подтверждено, почему важно, что будет, если не делать.
**Материалы:** код (`путь:строка`), журналы, документы.
```

Пояснения после `#` — только в этом образце: в файле задачи значение поля занимает строку до конца.
Поле `after` пишем, только когда задача ждёт других: пока они открыты, её нет в списках «быстрое» и
«на ночь». Взятая в работу задача получает ещё поле `taken`: кто и когда. После правки поля руками —
`{{COMMAND}} index`.

Метки (`tags`):

{{TAGS}}

По меткам `check` и `decision` INDEX.md делит то, что ждёт владельца, на «Проверить» и «Решить».
Новую метку сначала вписывают в `tags` у [config.json](config.json).

## Как работать

Всё через `{{COMMAND}}` — он же пересобирает INDEX.md и таблицы областей, руками их не правим.

| Нужно | Команда |
|---|---|
| Новая задача | `{{COMMAND}} new {{EXAMPLE_AREA}} "Заголовок" --p P2 --who {{AGENT}} --auto yes --effort 2h` — файл с шаблоном, дописать тело. Ещё `--tags check,bug`, `--related {{EXAMPLE_ID_2}}`, `--after {{EXAMPLE_ID_2}}`, `--due`, `--where`, `--from` |
| То же для другой области | `{{COMMAND}} port {{EXAMPLE_ID}} {{EXAMPLE_AREA_2}}` — задача со ссылкой на исходную |
| Идея с дороги | `{{COMMAND}} idea "текст"` или строка в [inbox.md](inbox.md) руками |
| Закрыть | `{{COMMAND}} done {{EXAMPLE_ID}} ok "что вышло, коммит"` — `ok` · `partial` · `failed` · `dropped` |
| Взять в работу | `{{COMMAND}} take {{EXAMPLE_ID}} "машина, сессия"`, отпустить — `release {{EXAMPLE_ID}}` |
| Где нужен владелец | `{{COMMAND}} list --owner` |
| Быстрое для агента | `{{COMMAND}} list --quick` |
| На ночь | `{{COMMAND}} list --night` — `autonomous: yes`, по приоритету |
| Отчёт владельцу | `{{COMMAND}} report` — Markdown: кто делает (агент сам, вместе, владелец), приоритет, блок и сумма оценок. Отбор — `--area`, `--p`, `--who`, `--block`, `--tag`; заголовки — `--group area,block`, строки — `--sort who,priority,effort` |
| Проверка | `{{COMMAND}} check` — поля, ID, ссылки, свежесть индекса |
| Задача оказалась в чужой области | `{{COMMAND}} move {{EXAMPLE_ID}} {{EXAMPLE_AREA_2}}` — новый номер там, ссылки на неё переписаны |
| Номер заняла другая сессия | `{{COMMAND}} reid {{EXAMPLE_ID}}` — следующий свободный номер |

Правила:

- Сессия читает INDEX.md, таблицу своей области и только файлы своих задач. Каталог целиком не
  читаем: ради этого сводки и собираются.
- Замеченную по ходу недоделку заводим задачей сразу, а не держим в памяти разговора.
- Сделанное закрываем командой `done`: файл задачи удаляется, в `done/<месяц>.md` встаёт строка с
  датой, итогом и комментарием — что вышло и каким коммитом. Частично сделанное — `partial`, а
  остаток — новой задачей; либо задачу не закрываем и правим её тело.
- `autonomous: yes` ставим, только когда агент может и сделать, и сам убедиться в результате. Если
  в конце нужен глаз или слово владельца — `partly`, если без него не начать — `no`.
- Крупная работа — задача с шагами в теле; шаг, который стоит сам по себе, — своя задача со
  ссылкой в `related`. Длинный план — отдельным документом рядом с кодом, задача ссылается на него.
- Работа на две области — две задачи со взаимными `related`: так каждая закрывается сама.
- Работа, которая ждёт шага владельца — учётной записи, ключа, решения, — это две задачи: короткая
  владельцу и своя агенту с `after` на неё. Владелец видит дело на несколько минут, а задача агента
  встаёт в списки, как только та закрыта.
- `inbox.md` разбирает любая сессия, когда владелец просит или строк больше десяти: строка
  становится задачей или уходит, если владелец её отклонил.
- Перед коммитом правки беклога — `{{COMMAND}} check`.

Несколько сессий разом:

- `new` берёт следующий свободный номер по файлам на диске и по уже полученной ветке сервера,
  поэтому перед ним — `git pull` или `git fetch`. Задачу заводим ближе к коммиту, а не в начале
  работы: номер свободен, только пока его не запушил другой.
- Если номер всё же совпал, `check` скажет об этом после слияния. `reid <ID>` даёт своей задаче
  новый номер и называет файлы, где остался старый; в журнале `done/` свою строку правим руками.
- INDEX.md и таблицы областей при конфликте не сливаем, а пересобираем: `{{COMMAND}} index`.
- Взятую задачу помечаем `take` и сразу пушим. Перед тем как взять задачу — `git pull`, и помеченную
  чужой сессией не берём. `done` снимает пометку вместе с файлом, брошенную задачу отпускает
  `release`.
